## JWT

- JSON WEB TOKEN의 약자로 속성 정보를 JSON 데이터 구조로 표현한 토근으로서 네트워크를 통해서 서로 다른 장치끼리 안전하게 전송하기 위해 설계된 데이터 조각

- 구성요소
    - header
    - payload
    - signature
- header : 해시 암호화 알고리즘과 토큰의 타입으로 구성
- payload : 내용, 즉 토큰에 담을 클레임 정보를 포함
    - payload에 담는 정보의 하 조각을 클레임이라고 부르며, name / value의 한 쌍으로 이뤄짐
    - 토큰에는 여러 개의 클레임 들을 넣을 수 있음
    - 등록된 클레임(registerd), 공개 클레임(public), 비공개 클레임(private)으로 3종류가 있음
        - 등록된 클레임 : 토큰 정보를 표현하기 위해 이미 정해진 종류의 데이터들로, 모두 선택적으로 작성이 가능
            - iss: 토큰 발급자(issuer)
            - sub: 토큰 제목(subject)
            - aud: 토큰 대상자(audience)
            - exp: 토큰 만료 시간(expiration)
            - nbf: 토큰 활성 날짜(not before)
            - iat: 토큰 발급 시간(issued at)
            - jti: JWT 토큰 식별자(JWT ID)
        - 공개 클레임 : 사용자 정의 클레임, 공개용 정보를 위해 사용
        - 비공개 클레임 : 사용자 정의 클레임으로, 서버와 클라이언트 사이에 임의로 지정한 정보를 저장
- signature : header, plyload, seceret key를 합쳐 암호화한 결과 값
    - header와 payload를 Base64Url 인코딩하여 문자열로 생성

## JWT 동작 방식

1. 사용자가 로그인을 시도
2. 서버는 요청을 확인하고 seceret key와 payload를 서명 알고리즘에 입력하여 서명을 만들고 이를 조립한 JWT를 발급
3. JWT 토큰을 클라이언트에 전달
4. 클라이언트에서 API를 요청할 때 클라이언트가 인증 헤더에 토큰을 담아서 보냄
    1. 인증/인가 처리
5. 서버는 JWT Signature를 체크하고 payload로부터 사용자 정보를 확인해 데이터를 반환
- 클라이언트의 로그인 정보를 서버 메모리에 저장하지 않기 떄문에 (stateless-무상태) 토큰기반 인증 메커니즘을 제공
- 인증이 필요한 경로에 접근할 때 서버 측은 인증 헤더에 유효한 jwt인지 또는 존재하는지 확인
- JWT에 필요한 모든 정보를 토큰에 포함하기 때문에 DB와 같은 서버와의 커뮤니켕이션 오버헤드를 최소화할 수 있음

## Access Token

- 역할 : 사용자가 인증(로그인) 후, 보호된 리소스(API등)에 접근할 때 필요한 신분증
- 클라이언트가 매 요청 시 API 호출에 이 토큰을 헤더에 담아 보냄
- 유효기간이 보통 짧음(5-30분)
- 서버는 토큰을 디코딩해서 사용자 정보를 꺼냄

## Refresh Token

- 역할 : 엑세스 토큰이 만료되었을 때, 새로운 엑세스 토큰을 발급받기 위한 열쇠
- 엑세스 토큰처럼 Authentication 헤더에 쓰지 않고,  보통 HttpOnly 쿠키로 저장해서 클라이언트가 직접 다루지 않도록 함
- 유효기간이 보통 길다 (7일-몇달)
- 서버가 DB등에 저장해서 유효성을 검증할 수 있도록 관리
